## Назначение папок

Вся сборочная логика вынесена из `gulpfile.js` — он остаётся только точкой входа. Это упрощает поддержку и позволяет переиспользовать конфигурацию между проектами.

| Папка | Что внутри | Когда править |
| --- | --- | --- |
| `config/` | Пути, настройки задач, экземпляр BrowserSync | При добавлении новых путей или изменении поведения задач |
| `tasks/` | По одной задаче на файл | При изменении логики конкретной задачи |
| utils/ | Вспомогательные модули (сервер, watcher, shutdown, хелперы шаблонов) | При добавлении инфраструктурных функций |

### `src/`

| Папка | Назначение |
| --- | --- |
| `pug/` | Все шаблоны. `index.pug` и `pages/*.pug` — точки входа, остальное — партиалы и миксины |
| `data/` | JSON-данные, инжектируемые в Pug на этапе сборки. Не для **runtime** — читаются один раз при сборке |
| `assets/sass/` | SCSS-исходники. Компилируются в `build/assets/css/` |
| `assets/css/` | Готовый CSS, который не нужно компилировать (vendored-стили). Копируется в билд как есть |
| `assets/js/` | JavaScript. `main.js` — точка входа для webpack |
| `assets/images/` | Изображения. Оптимизируются `imagemin` |
| `assets/fonts/` | Шрифты. Копируются без обработки |

### `build/`

Результат сборки. Полностью генерируется — не редактируется вручную и не коммитится в git (см. `.gitignore`).
